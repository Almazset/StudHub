# Права доступа StudHub

Проверено 15.11.2026. Каталог курсов меняет только ADMIN — это правило
подтверждено владельцем проекта. Роль администратора не даёт общего доступа
к чужим личным заданиям, закрытым профилям, проектам и перепискам.

## Границы доверия

Аккаунт берётся из серверной сессии. ID в URL, JSON и формах не доказывает
владение. Для объектов проверяются владелец/членство, для административных
операций — роль на сервере. Скрытие кнопок служит только удобству интерфейса.
Регистрация всегда создаёт USER, поля роли и чужого ID в настройках не
предоставляют дополнительных прав.

## Матрица доступа

| Раздел | Чтение | Изменение |
| --- | --- | --- |
| Каталог курсов | Любой вошедший пользователь | Создание, редактирование и удаление — ADMIN; защита HTML, API и CourseService |
| Личные задания | Только владелец | Только владелец, включая статус и удаление; см. assignment-access.md |
| Прогресс курса | Только текущий аккаунт | Свои этапы; чужой ID не даёт доступа |
| Проекты | Владелец и участники | Название, описание и состав команды — владелец |
| Задачи проекта | Владелец и участники | Участники создают, меняют и переключают статус; удаляет владелец проекта; исполнитель должен состоять в проекте |
| Глобальный чат | Все вошедшие пользователи | Отправка всем; изменение/удаление сообщения только автором |
| Личные/групповые чаты | Только участники | Сообщения — только автором; добавление участников группы — владельцем группы |
| Чат проекта | Участники проекта | Состав синхронизируется с проектом; удалённый участник теряет доступ |
| Профили и фото | Свой профиль либо профиль с видимостью members | Только владелец через настройки |
| Настройки, пароль, 2FA, фото | Только текущий аккаунт | Текущий аккаунт; чувствительные операции дополнительно проверяют пароль/2FA |
| Сеансы | Только свои | Отзыв чужого сеанса запрещён |
| Поддержка | Пользователь видит свои обращения; ADMIN — входящие | Закрытие обращения — ADMIN |
| Пользователи и роли | ADMIN | ADMIN |
| Новости | Все вошедшие пользователи | Публикация, редактирование, удаление — ADMIN |
| AI и лекции | Автор текущего запроса | Загрузка только после входа и с CSRF; данные запроса не подмешиваются другим аккаунтам |

Поиск пользователей учитывает видимость профиля. Публичный профиль не
содержит email, хэш пароля, роль, секрет 2FA и резервные коды. Эти правила
сохраняются и при попытке администратора открыть закрытый профиль.

## Исправления

1. Курсы были доступны для изменения любому вошедшему пользователю.
   Добавлены серверные проверки ADMIN, ограничение полей формы и удалены
   недоступные кнопки для USER.
2. При изменении роли/email через административный API и удалении аккаунта
   отзываются прежние сеансы. Понижение роли не оставляет старую сессию ADMIN.
3. Черновик задания из AI раньше использовал общий ключ sessionStorage.
   Теперь ключ привязан к ID аккаунта; старые и чужие черновики удаляются
   при открытии помощника в новой странице аккаунта.
4. Отказ в POST/PUT/DELETE мог возвращать 405 из-за перенаправления на GET-only
   страницу отказа. API теперь получает 403 с JSON FORBIDDEN; HTML — страницу
   отказа с сохранением 403.

## Что проверено, но не добавлено

Проекты, задачи проектов, чаты, прогресс курсов и профили уже имеют проверки
владельца/членства. Проверены эти существующие правила и добавлены сценарии,
где посторонний пользователь имеет роль ADMIN.

Лекции AI обрабатываются в рамках запроса; постоянной библиотеки загруженных
материалов и выдачи их другим пользователям по ID сейчас нет. Gemini получает
только материалы и историю из текущего запроса, без чтения пользовательской
базы. Для будущего файлового архива нужны отдельные правила доступа; текущая
проверка не означает, что такой архив реализован.

У проекта сейчас нет серверного маршрута закрытия/удаления проекта. Он не
проверяется как существующая функция; удаление задач проекта доступно владельцу.

- SectionAccessTest: курсы, серверный сервис, административные маршруты,
  регистрация, настройки, приватность профилей/фото, отзыв сеансов,

  чужие ID, поиск, действия с задачами и синхронизация чата проекта.
- SettingsSecurityMvcTest / AccountSecurityTest: личные настройки, сеансы,
  пароль/2FA, поддержка и отсутствие секретов в ответах.
- AssistantApiSecurityTest: вход, CSRF, валидация загрузок и отсутствие лекции
  первого аккаунта в следующем запросе другого.
- Chrome + PostgreSQL: обычный пользователь и временный ADMIN, создание/
  изменение/удаление курса, реальные повышение/понижение роли с истечением
  сеанса, закрытый проект, авторство сообщений, отзыв участника и черновики
  AI при смене аккаунтов в одной вкладке.
- Реальный запрос к Gemini не выполнялся: изоляция запросов проверена
  подменой провайдера в тестах, без передачи лекций внешнему сервису.
- Временные аккаунты и данные удалены, сервер перезапущен для очистки сеансов.
