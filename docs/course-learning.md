# Курсы, внутренние уроки и прогресс

## Где проходит обучение

Курс с непустой HTTPS-ссылкой `externalUrl` обозначен как внешний. Его материалы и официальный прогресс находятся у автора. Кнопка «Продолжить обучение на сайте автора» открывает страницу курса в новой вкладке; StudHub не знает номер урока во внешнем аккаунте и не синхронизирует результаты.

Курс без внешней ссылки обозначен как внутренний. Администратор публикует собственные текстовые уроки в разделе «Управление уроками» на странице курса: название/порядок раздела, название/порядок урока, материал. Уроки сортируются по разделу, порядку урока и ID. Для уроков одного раздела указывайте одинаковые название и порядок раздела. Пустой курс явно сообщает, что материалы ещё не опубликованы; фиктивный прогресс не показывается.

Существующие три курса каталога остаются внешними. Их закрытые материалы не копировались. Полноценные внутренние курсы потребуется наполнить собственными материалами через интерфейс администратора.

## Инструкции и карточки

В форме курса есть язык материалов, инструкция начала и условия доступа с датой проверки. Текст экранируется. Если язык не указан, так и написано. Внешние курсы дополнительно показывают последовательность входа на платформу автора; внутренние — порядок открытия урока и ручной отметки. Каталог различает оба типа и содержит переход «Продолжить обучение».

## Прогресс

- Открытие внутреннего урока сохраняет последнюю посещённую страницу, но не завершает её автоматически.
- Чекбокс «Отметить урок пройденным вручную» сохраняет результат в PostgreSQL для текущего аккаунта. Отметку можно снять.
- Продолжение открывает последний посещённый незавершённый урок, иначе первый незавершённый. После завершения всех уроков кнопка предлагает повторить курс.
- Старые личные этапы `study_steps` сохранены отдельно как «Мой личный план · ручные отметки». Они не являются программой курса или подтверждением успешной сдачи.
- Изменение материала урока сохраняет отметки; они не служат сертификатом и не доказывают изучение обновлённой версии. Удаление урока требует подтверждения и удаляет его отметки. Остальные уроки/отметки сохраняются.

## Доступ и API

`/api/courses/{courseId}/lessons` доступен авторизованным пользователям общедоступного каталога. Создание, изменение и удаление уроков разрешены только ADMIN. API сверяет принадлежность урока курсу; все изменения требуют CSRF. Личный прогресс определяется по вошедшему аккаунту, поле чужого userId игнорируется. Для внешнего курса локальные уроки возвращают 409.

- GET коллекции: программа, личные отметки, resumeId, completedCount, allCompleted.
- GET `/{id}`: текст выбранного урока.
- POST `/{id}/visit`: запомнить посещение.
- PUT `/{id}/progress`, JSON `{"completed":true}`: ручная отметка.
- POST коллекции / PUT `/{id}`: sectionTitle, sectionOrder, lessonOrder, title, content.
- DELETE `/{id}`: удалить урок и его отметки.

До 100 уроков на курс, до 20 000 символов материала. Материал выводится обычным текстом: HTML/скрипты не выполняются. Уникальность пары пользователь–урок защищена ограничением базы. Записи прогресса и редактирование программы сериализуются блокировкой курса. Удаление курса удаляет новые уроки/отметки в той же транзакции; существующие ограничения связанных заданий могут отклонить удаление целиком.

## Обновление базы

Остановить приложение, создать копию по [RECOVERY.md](../database/RECOVERY.md), затем из корня проекта:

```powershell
Get-Content -Raw .\database\migrations\V003__course_lessons.sql | docker exec -i studhub-db psql -U studhub -d studhub -v ON_ERROR_STOP=1
Get-Content -Raw .\database\migrations\V004__course_catalog_review_20261116.sql | docker exec -i studhub-db psql -U studhub -d studhub -v ON_ERROR_STOP=1
```

V003 создаёт поля курса, `course_lessons` и `lesson_progress`. V004 обновляет только записи с тремя точными URL каталога; перед применением к другой базе проверьте, не изменены ли их описания вручную. Оба сценария повторяемы, каждый выполняется в транзакции. В локальной базе уже применены после резервного копирования.
