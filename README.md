# StudHub — Student Learning Management Platform

Самостоятельный проект для развитии. StudHub позволяет регистрироваться, входить в систему, управлять курсами и заданиями. Проект демонстрирует Spring Boot, Spring MVC + Thymeleaf, Spring Data JPA, PostgreSQL, Spring Security, REST API, валидацию и тестирование.

Структура проекта описана в [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md). Навигационные разделы: [frontend](frontend/README.md), [backend](backend/README.md) и [database](database/README.md).

## Технологии
- Java 21, Spring Boot 3.5
- Spring MVC, Thymeleaf, Spring Security
- Spring Data JPA / Hibernate
- Docker Desktop с Docker Compose (для запуска PostgreSQL через Docker)
- Bean Validation
- Swagger / OpenAPI
- JUnit 5, Mockito

## Интерфейс
- Серверные страницы на Thymeleaf: обзор, курсы, задания, регистрация/вход и администрирование пользователей.
- Адаптивная навигация с мобильной панелью, светлой/тёмной темой, поиском, фильтрами и сортировкой.
- Bootstrap 5.3.8, Bootstrap Icons 1.13.2 и шрифты Inter / Space Grotesk хранятся локально в `src/main/resources/static`; сборка frontend не требуется.
- Локализация интерфейса: `src/main/resources/messages.properties`.
- Статический макет предпросмотра: `docs/studhub-preview.html`. Он использует те же CSS и JS, что и приложение.

## Требования
- JDK 21
- Maven 3.9+ (или Maven Wrapper, если добавить его в IDE)
- PostgreSQL

## Локальный запуск с PostgreSQL
Для уже использовавшейся базы сначала выполните [переход на Flyway](database/README.md). На новой базе Flyway создаёт схему при первом запуске StudHub.

1. Запустите Docker Desktop и из корня проекта скопируйте `.env.example` в `.env`, если файла ещё нет. PostgreSQL для разработки будет доступен на `127.0.0.1:15432`. Если меняете настройки подключения, используйте одинаковые значения для контейнера и приложения.
2. Запустите базу:
   ```bash
   docker compose up -d --wait
   ```
3. При необходимости создайте первого администратора до запуска приложения. В PowerShell из корня проекта задайте обе переменные окружения в той же сессии, из которой запустите приложение. Введите ещё не зарегистрированный email и новый пароль длиной не менее 12 символов:
   ```powershell
   $env:STUDHUB_ADMIN_EMAIL = Read-Host 'Email администратора'
   $adminPassword = Read-Host 'Пароль администратора (не менее 12 символов)' -AsSecureString
   $adminPasswordPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($adminPassword)
   try {
       $env:STUDHUB_ADMIN_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($adminPasswordPointer)
   } finally {
       [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($adminPasswordPointer)
       $adminPassword.Dispose()
   }
   ```
   При запуске с обеими переменными приложение создаст администратора, если аккаунта с таким email ещё нет. Если email уже зарегистрирован, роль и пароль существующей учётной записи не изменятся. При незаданных переменных администратор не создаётся. Если задана только одна переменная или пароль короче 12 символов, запуск завершится ошибкой.

4. Запустите приложение из корня проекта в той же сессии PowerShell. По умолчанию активен профиль `dev`. Docker Compose читает `.env` автоматически. Spring Boot использует настройки профиля и переменные процесса.
   ```bash
   mvn spring-boot:run
   ```
   Если изменили `.env`, передайте те же `DB_URL`, `DB_USERNAME` и `DB_PASSWORD` в окружение процесса приложения. Пример для PowerShell (пароль вводите у себя):
   ```powershell
   $env:DB_URL = "jdbc:postgresql://localhost:15432/studhub"
   $env:DB_USERNAME = "studhub"
   $env:DB_PASSWORD = "ваш_локальный_пароль"
   mvn.cmd spring-boot:run
   ```
5. Если вы задали данные администратора, откройте `http://localhost:8080/login` и войдите с ними. Обычного пользователя можно создать через `http://localhost:8080/register`. Таблицы можно проверить командой:
   ```bash
   docker exec -it studhub-db psql -U studhub -d studhub -c "\dt"
   ```
   Если поменяли пользователя или имя базы, замените их и в команде проверки. Swagger UI: `http://localhost:8080/swagger-ui.html`.

При `Connection refused` проверьте `docker compose ps` и доступность порта 15432. При `password authentication failed` сверяйте настройки приложения с паролем контейнера. При `database does not exist` проверьте имя базы в URL. Переменные `POSTGRES_*` применяются при первой инициализации тома. Для смены пароля существующей базы обновите его внутри PostgreSQL и в настройках подключения.

Переменные администратора относятся к процессу приложения и не загружаются Spring Boot из файла `.env`. После завершения работы их можно удалить из текущей сессии PowerShell командами `Remove-Item Env:STUDHUB_ADMIN_EMAIL` и `Remove-Item Env:STUDHUB_ADMIN_PASSWORD`.

## Запуск на сервере

Соберите приложение командой `mvn verify`. Для процесса `java -jar target/studhub-0.0.1-SNAPSHOT.jar` установите `SPRING_PROFILES_ACTIVE=prod`, `DB_URL` с префиксом `jdbc:postgresql://`, `DB_USERNAME` и `DB_PASSWORD`. Задайте `STUDHUB_2FA_KEY` через хранилище секретов. Ключ содержит 32 байта в Base64. При переносе существующего приложения сохраните его действующий ключ.

В профиле `prod` Flyway выполняет миграции, а Hibernate проверяет схему при запуске. Приложение требует явные настройки базы и ключа 2FA, включает Secure для сессионной cookie и отключает Swagger. Размещайте его за HTTPS-прокси. `GEMINI_API_KEY` требуется только при использовании StudHub AI.

Для проверки готовности выполните `curl.exe -fsS http://127.0.0.1:8080/actuator/health/readiness`. Readiness проверяет PostgreSQL и готовность приложения принимать запросы. `/actuator/health/liveness` проверяет приложение независимо от базы. `/actuator/health` показывает сводный статус. Ответы содержат статус без конфигурации и внутренних деталей.

Журналы пишутся в stdout. Для хранения и ротации используйте журнал службы или контейнера. Приложение маскирует настроенные секреты и не выводит стеки исключений. Ошибки HTTP 5xx можно сопоставить с журналом по заголовку ответа `X-Request-ID`.

После первого запуска выберите `Build and PostgreSQL` в [правилах защиты main](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches#require-status-checks-before-merging), чтобы GitHub требовал успешную проверку перед слиянием.

## Настройки аккаунта

В меню шестерёнки доступны четыре раздела. Тема, размер текста и язык (русский, казахский, английский) применяются сразу; в приложении они сохраняются в аккаунте. Пользователь может изменить имя и фото (PNG/JPEG до 2 МБ), email и пароль. При смене email требуются текущий пароль и код 2FA, если защита включена; после изменения нужно войти снова. При смене пароля остальные сеансы завершаются.

Двухфакторная защита использует TOTP (6 цифр, 30 секунд). Секрет вводится вручную в приложение-аутентификатор, затем подтверждается кодом. При включении выдаются восемь одноразовых резервных кодов. Они показываются один раз; на сервере сохраняются только их хеши. Для защищённого аккаунта поле кода на странице входа обязательно. Повторное использование TOTP отклоняется; после восьми неверных кодов действует пауза 5 минут.

Секреты TOTP зашифрованы AES-GCM. Для опубликованного приложения задайте `STUDHUB_2FA_KEY` (32 случайных байта в Base64) через хранилище секретов. При локальном запуске ключ создаётся в `.studhub/security.key`; каталог исключён из Git. Сохраняйте ключ вместе с защищённой резервной копией конфигурации: его потеря делает настроенные TOTP недоступными. При работе по HTTPS установите `SESSION_COOKIE_SECURE=true`.

Учёт сеансов рассчитан на один экземпляр приложения. В списке показываются браузер, ОС и последняя активность; IP-адрес не сохраняется. Завершённый сеанс блокируется при следующем запросе. При перезапуске серверные HTTP-сеансы прекращаются. Для нескольких экземпляров потребуется общее хранилище сеансов.

В «Настройки → Приватность и безопасность» можно отдельно выбрать аудиторию профиля, личных сообщений и статуса. Видимый профиль показывает имя и фото. Поиск по SH-ID возвращает только ID и отображаемое имя, если профиль доступен. Email виден владельцу аккаунта и администратору в управлении пользователями.

Раздел «О сайте» содержит FAQ, правила учебного сервиса, версию и форму поддержки. Обращения сохраняются в базе; администратор открывает их в том же разделе и может закрыть обработанные заявки. Отправка email внешним сервисам не используется.

Для предпросмотра выполните `node docs/preview-server.cjs` и откройте `http://127.0.0.1:8765/docs/studhub-preview.html#settings-appearance`. В нём имя, фото, email, внешний вид и обращения сохраняются только в браузере. Смена пароля, 2FA и управление настоящими сеансами доступны в запущенном Spring Boot приложении. Сервер предпросмотра раздаёт только файлы интерфейса, без конфигурации и ключей.

## Друзья и приватность

В разделе «Друзья» и в чате есть действия для блокировки и отправки жалобы. Блокировка удаляет дружбу или текущую заявку, скрывает профили и ограничивает новые личные сообщения и заявки в обе стороны. История личной переписки сохраняется. Разблокировка доступна во вкладке «Заблокированные» и не восстанавливает дружбу автоматически.

Список друзей обновляется примерно каждые 15 секунд, пока вкладка видима. После закрытия сайта статус «Не в сети» может появиться с задержкой до полутора минут. Скрытый статус видит только сам пользователь. Жалобы сохраняются в базе и доступны администраторам в разделе «Пользователи».

При переносе старой базы миграцию приватности учитывает [инструкция перехода на Flyway](database/README.md).

## Уведомления

Колокольчик показывает новые сообщения в личных, групповых и проектных чатах, приглашения в проект, заявки в друзья, назначение задач и напоминания о сроках. Сообщения одной переписки объединяются в одну запись. Уведомление можно прочитать отдельно или отметить все прочитанными.

Напоминания о незавершённых задачах появляются при обновлении ленты за три календарных дня до срока с учётом часового пояса браузера. При выполнении или переносе задачи лента убирает устаревшее напоминание. В разделе «Настройки → Уведомления» каждый тип можно включить отдельно. Настройки и отметки о прочтении сохраняются в PostgreSQL. Миграция `V009__notifications.sql` добавляет таблицы ленты и настроек.

## Новости StudHub

В разделе «Новости» можно выбрать обновления StudHub, курсы, анонсы или полезные материалы. У внешних публикаций указываются название источника, дата публикации у источника и ссылка. Обновления StudHub помечаются как «Планируется», «В разработке» или «Выпущено».

Администратор открывает «Управление публикациями» из ленты. Там можно найти запись по заголовку, сохранить черновик, опубликовать, снять с публикации, исправить или удалить новость. Черновики видны администраторам.

Для базы до появления черновиков примените шаг V011 из [инструкции перехода на Flyway](database/README.md).

## Календарь и планирование

Календарь показывает сроки личных заданий, заданий курсов и задач открытых проектов, назначенных вам. Переключайтесь между днём, неделей и месяцем. Блок «Что учить сегодня» собирает записи плана на текущий день и до трёх срочных незавершённых задач. В личном плане можно задать дату и длительность занятия, перенести его или отметить выполненным.

Дедлайны и записи плана хранятся как календарные даты без времени. Часовой пояс браузера определяет «сегодня» и отметки о сроках. Неделя начинается в понедельник. API календаря — `GET /api/calendar`, личного плана — `/api/calendar/plan`. Таблицу плана добавляет миграция `V008__study_plan.sql`.

## Учебный ИИ-ассистент

В **StudHub AI** можно обработать до трёх лекций за запрос, сохранить конспект с терминами, повторить материал по карточкам, пройти тест и составить план подготовки. Для сложной задачи помощник объясняет ошибку и предлагает следующий шаг. AI открывает черновик задания в обычной форме: запись создаётся при сохранении пользователем. Гид по сайту работает без модели.

Для реальных ответов задайте `GEMINI_API_KEY` на сервере. По умолчанию используется `gemini-3.8-flash`; модель меняется через `GEMINI_MODEL`. Ключ не передаётся браузеру. [Инструкция подключения, форматы файлов и обработка данных](docs/GEMINI_SETUP.md).

## Чаты

В разделе `/chat` доступны личные сообщения, группы до 30 участников и общий чат StudHub. Есть поиск открытых профилей, история, непрочитанные сообщения и отправка ссылок. Сообщения сохраняются в PostgreSQL и автоматически обновляются на открытом экране. [Поведение, доступ и API чатов](docs/CHAT.md). Ответы, реакции, пересылка, избранное, закрепления и восстановление связи описаны в [доработке текстового чата](docs/text-chat.md).

В HTML-предпросмотре `#chat` работает локальная демонстрация без доставки сообщений другим людям.

## Тестирование

### Обновлённый интерфейс StudHub

Общий стиль страниц находится в `src/main/resources/static/css/themes.css`.
Светлая тема используется при первом посещении, выбранная пользователем тема сохраняется.
Сменить её можно в «Настройки → Внешний вид». Поддерживаются светлый и тёмный режимы;
автоматическое переключение по теме операционной системы пока не добавлено.
График «Нагрузка на неделю» строится по заданиям отображаемого календаря, а его столбцы
ведут к заданиям. На мобильном экране календарь прокручивается внутри своей карточки.
Анимации учитывают системную настройку уменьшения движения.

Запуск приложения: `mvn spring-boot:run` (PostgreSQL должен быть запущен).
Откройте `http://localhost:8080/`. Для отдельного демонстрационного предпросмотра:
`node docs/preview-server.cjs`, затем `http://127.0.0.1:8765/docs/studhub-preview.html`.
Предпросмотр содержит демонстрационные данные; он не подключается к PostgreSQL.
После обновления файлов используйте Ctrl+F5. При запуске из JAR сначала пересоберите
его командой `mvn package -DskipTests`, затем перезапустите приложение.

```bash
mvn test
```

## Важные замечания перед защитой
- Обычная регистрация создаёт только роль `USER`. Создание, изменение и удаление пользователей через `/api/users` и страница `/users` защищены ролью `ADMIN`. Администратор создаётся при запуске с заданными `STUDHUB_ADMIN_EMAIL` и `STUDHUB_ADMIN_PASSWORD`, если аккаунта с этим email ещё нет.
- CRUD API курсов и заданий доступен после входа. CRUD API пользователей доступен только ADMIN.
- Схему PostgreSQL обновляет Flyway. В рабочих профилях Hibernate проверяет её с `spring.jpa.hibernate.ddl-auto=validate`.
- Перед сдачей дополните README скриншотами своей работы, схемой ER, списком осмысленных Git-коммитов и результатами тестов.
