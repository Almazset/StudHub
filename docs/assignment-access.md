# Доступ к заданиям

Личное задание принадлежит аккаунту в `assignments.student_id`. При создании
владелец определяется сервером по аутентифицированному аккаунту. Поля `id`,
`student` и `course` из HTML-формы не привязываются; курс выбирается через
отдельный параметр `courseId`. Создание всегда создаёт новую запись.

AssignmentService применяет ограничение владельца ко всем операциям, включая
списки, чтение, обновление, удаление и переключение выполнения. Главная,
уведомления о сроках, страница курса и API используют тот же сервис.
Чужое и отсутствующее задание возвращают 404. Роль ADMIN не открывает личные
задания других аккаунтов. API не принимает владельца и проверяет длину полей.

## Старые записи

Записи с `student_id IS NULL` сохранены, но не являются общедоступными:
они не показываются и не изменяются через личные задания. Не назначайте их
первому вошедшему пользователю или всем администраторам.

Перед ручным восстановлением владельцев создайте резервную копию, изучите
список таких записей и подтвердите соответствие задания конкретному аккаунту.
Назначение выполняется отдельно, с условием `student_id IS NULL` и проверкой
числа изменённых строк. Существующие ненулевые владельцы не меняются.

## Общие задачи

Совместная работа остаётся в задачах проектов (`project_tasks`) с проверкой
участия в проекте. Общий доступ к курсу не делает личные задания общими.
Отдельных общих заданий курса и правил их раздачи пока нет; добавлять их
следует отдельной моделью доступа, а не трактовать NULL как публичность.

## Проверка

`AssignmentOwnershipTest` создаёт два независимых аккаунта в тестовой H2 и
проверяет списки, dashboard, курс, API, подмену владельца/ID, чужие операции,
старые записи без владельца, успешные операции владельца, CSRF и валидацию.
Рабочие пользовательские данные этим тестом не затрагиваются.

API возвращает явные поля задания и курса, без Hibernate-прокси и данных
аккаунта. Дата формы редактирования имеет ISO-формат, совместимый с полем date.

Проверка 14.11.2026: все 73 теста прошли, сборка JAR успешна.
В Chrome с двумя временными аккаунтами и PostgreSQL проверены создание и
редактирование через формы, отсутствие чужих заданий в списках, ответы 404
при чужих чтении, изменении, удалении и переключении статуса.
Временные аккаунты и их задания после проверки удалены.
До проверки в локальной таблице assignments записей не было: восстанавливать
владельцев старых заданий в этой базе не потребовалось.
