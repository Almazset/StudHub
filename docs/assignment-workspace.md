# Задания: личные, по курсам и задачи проектов

## Что доступно пользователю

На странице `/assignments` собраны три вида записей:

- **Личное**: задание без курса, доступное только владельцу.
- **По курсу**: личное задание со ссылкой на курс. Доступ к курсу не открывает чужие задания.
- **Задача проекта**: общая задача команды, доступная владельцу и участникам проекта. Ссылка открывает конкретную задачу на странице проекта.

Фильтр «Мои» показывает первые два вида; «Назначены мне» — задачи доступных проектов, где текущий пользователь указан исполнителем. «Все» включает остальные задачи его команд. После удаления участника из проекта его задачи перестают отображаться этому пользователю, даже если он остался указан исполнителем.

Фильтры «Просрочено», «Выполнено», «Незавершённые» можно сочетать с типом, приоритетом, курсом и поиском по названию задания или связанного курса/проекта. В календаре показываются только записи с дедлайном. Проектные задачи без срока остаются в списке и не считаются просроченными.

Личные задания и задания курса имеют состояния «Запланировано», «В работе», «Выполнено». В проектах также есть «На проверке». Приоритеты: низкий, средний, высокий. У личного задания дедлайн обязателен; в проекте он может отсутствовать. Повторное открытие выполненного личного задания переводит его в «Запланировано».

Удаление личного задания подтверждается окном с его названием. Проектная задача удаляется на странице проекта с подтверждением, только владельцем проекта. Редактирование, назначение исполнителя и изменение статуса проекта используют прежние серверные проверки участия. Создание общих заданий курса преподавателем и раздача их группе не входят в эту модель.

## Обновление существующей PostgreSQL

Новые поля: `assignments.status`, `project_tasks.priority`. Связь `assignments.course_id` становится необязательной. Поле `completed` сохранено для совместимости и синхронизируется со статусом. Старые записи получают DONE/TODO и средний приоритет соответственно; владельцы и даты не изменяются.

1. Остановите приложение, оставив PostgreSQL запущенным.
2. Создайте копию по [инструкции восстановления](../database/RECOVERY.md).
3. Из корня проекта выполните (для стандартной роли и базы `studhub`):

```powershell
Get-Content -Raw .\database\migrations\V001__assignment_types_and_status.sql | docker exec -i studhub-db psql -U studhub -d studhub -v ON_ERROR_STOP=1
```

4. Только после успешного COMMIT запускайте обновлённое приложение. При ошибке выполнение откатывается транзакцией; выясните причину перед запуском.

Сценарий можно применять повторно. Он нужен для существующей базы: одного Hibernate `update` недостаточно для надёжного снятия NOT NULL. Автоматический движок миграций этим изменением не добавлен.
