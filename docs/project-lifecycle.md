# Проекты: закрытие, приглашения и история

## Пользовательские действия

- Владелец закрывает проект с подтверждением и может открыть его повторно. Название, описание, задачи, исполнители, участники и события сохраняются.
- Закрытый проект виден прежним участникам. Изменения проекта, состава команды и задач запрещены на сервере. Просмотр, фильтрация и история доступны. Чат команды продолжает работать: закрытие планирования не удаляет переписку и не прекращает общение.
- Владелец и участники подписаны в списке команды. Только владелец меняет описание, приглашает и удаляет участников, закрывает/открывает проект и удаляет задачи. Участники открытого проекта могут создавать/редактировать задачи и менять их статусы.
- Приглашение появляется у адресата в разделе «Проекты». До принятия оно не даёт доступа к проекту, задачам, истории или чату. Адресат может принять или отклонить его; владелец — отменить. В закрытый проект вступить нельзя, отклонить приглашение можно.
- Лимит 30 включает участников и ожидающие приглашения. Повторная отправка одного приглашения не создаёт дубликат. Старые участники сохраняют доступ без повторного приглашения.
- Фильтры задач сочетаются: статус, исполнитель (в том числе «Не назначен»), диапазон дат включительно, «Без срока», «Только мои», «Просроченные» и поиск. Кнопка сброса очищает все условия. Если начало периода позже конца, совпадений нет.

## История и доступ

В истории фиксируются создание/редактирование проекта, закрытие/открытие, отправка/принятие/отклонение/отмена приглашений, удаление участника, создание/редактирование/удаление задач и смена статуса. События содержат время UTC, публичный SH-ID действовавшего пользователя и описание. Они создаются в одной транзакции с действием. Отказ в доступе или ошибка не оставляют успешного события.

История видна только текущим участникам и владельцу; роль ADMIN не открывает чужие проекты. После исключения участник теряет доступ. История выдаётся порциями по 50 записей с курсором `before`; старые события не удаляются. История прошлых изменений до внедрения функции не выдумывается.

Изменения проекта, задач и приглашений используют блокировку строки проекта, чтобы закрытие не соревновалось с записью задачи или принятием приглашения. Все изменяющие запросы требуют CSRF.

## API

- `PATCH /api/projects/{id}/state`, JSON `{"closed":true}` или `false` — владелец.
- `POST /api/projects/{id}/members` теперь **отправляет приглашение**, а не добавляет участника немедленно. JSON `{"userId":123}`.
- `GET /api/projects/invitations` — только входящие приглашения текущего аккаунта.
- `POST /api/projects/{id}/invitation/accept` или `/decline` — только адресат.
- `DELETE /api/projects/{id}/invitations/{userId}` — отмена владельцем.
- `GET /api/projects/{id}/history?before=123` — история доступного проекта.

Закрытый проект возвращает 409 при попытке изменения; чужой/недоступный — 404. Клиент показывает сообщение о невозможности действия и предлагает проверить состояние проекта. Изменение договора `/members` учтено в интерфейсе и интеграционных тестах.

## PostgreSQL

После резервного копирования и остановки приложения примените из корня проекта:

```powershell
Get-Content -Raw .\database\migrations\V002__project_lifecycle.sql | docker exec -i studhub-db psql -U studhub -d studhub -v ON_ERROR_STOP=1
```

Сценарий добавляет `study_projects.closed`, таблицы `study_project_invitations` и `study_project_events`, индекс истории. Повторное применение допустимо. Старые проекты открыты по умолчанию. Автоматический движок миграций пока не добавлен. Инструкция резервного копирования: [RECOVERY.md](../database/RECOVERY.md).

## Проверка

109 тестов проходят, сборка JAR успешна. Новые `ProjectLifecycleTest` проверяют отсутствие доступа до принятия, права адресата/владельца, CSRF, закрытие/открытие без потери данных, запрет изменений закрытого проекта, отмену/отклонение приглашений, приватность и постраничную историю. Существующие тесты командного чата теперь принимают приглашение перед проверками участия.

В Chrome и PostgreSQL проверены два аккаунта, создание проекта, приглашение через поиск SH-ID, принятие, роли, фильтры, закрытие/открытие, история и мобильная ширина 390 px. Перед локальным обновлением базы создана резервная копия. Временные аккаунты используются только для проверки и удаляются после неё.
